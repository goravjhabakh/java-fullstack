# Learning Plan

## Goal

Become comfortable building production-style full-stack applications using Java and Spring Boot.

The learning process is project-driven.

Concepts should be introduced when they become useful rather than studied in isolation.

---

## Phase 1 — Spring Fundamentals

Learn:

- Spring Boot project structure
- controllers
- HTTP endpoints
- request/response handling
- JSON serialization
- dependency injection
- services
- basic Java collections in application code

Build:

A small in-memory Task API.

---

## Phase 2 — API Engineering

Learn:

- REST API design
- DTOs
- validation
- HTTP status codes
- exception handling
- application layering

Build:

Expand the Task API into a small project/task management backend.

---

## Phase 3 — Persistence

Learn:

- PostgreSQL
- relational data modelling
- Spring Data JPA
- Hibernate
- entities
- repositories
- database migrations
- transactions

Build:

Replace in-memory storage with PostgreSQL.

---

## Phase 4 — Real Backend Features

Learn:

- filtering
- sorting
- pagination
- relationships
- custom queries
- configuration
- logging

Build:

Turn the application into a small issue tracker.

---

## Phase 5 — Full Stack

Learn:

- frontend/backend integration
- API clients
- CORS
- async state
- error handling across layers

Frontend:

- React
- TypeScript
- TanStack Query
- TanStack Router

Build:

A complete issue-tracking web application.

---

## Phase 6 — Authentication and Security (Complete)

Learn:

- Spring Security
- authentication
- authorization
- password handling
- session-based Spring Security authentication
- ownership authorization
- BCrypt password handling
- CSRF and credentialed CORS

Add session authentication and user-owned data boundaries to the existing application.

---

## Phase 7 — Production Engineering

Introduce when useful:

- Redis
- caching
- background processing
- Docker
- health checks
- metrics
- structured logging
- CI/CD
- broader integration testing strategy

---

## Phase 8 — Final Project

Build a larger application independently.

Potential direction:

Workflow / operations management platform.

The user should make more architecture and implementation decisions with less AI guidance than in earlier phases.
